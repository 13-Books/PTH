Why plain text

Plain text is the oldest file format that still wins. It does not confuse what a sentence says with how an app draws it. You can open it decades from now, pipe it through a terminal, hand it to a typesetter, or feed it to a model — same bytes, same meaning.

  • Longevity: every computer already speaks it.
  • Freedom: your manuscript is not locked inside one word processor.
  • Power: small tools compose, because they share one language.

MarkBreak keeps a manuscript’s roles and page breaks inside that format, where they belong.

The mission

A manuscript should say what it is, and where it breaks,
without asking an app to remember for it.

That is the whole mission. Standard Markdown never recorded a print role, and never recorded a flow break — so “chapter”, “epilog”, and “turn the page” lived as formatting, memory, or folklore. MarkBreak puts them back in the file, in plain text, where they belong.

What we broke

  • --- stays a pause in the scene — Markdown never had a page break. //break is the one that turns the page.
  • A heading no longer has to guess a file's print role. The role says it, once, in the front matter.
  • “New page” is no longer a button pressed inside one app and forgotten by the file. It is a line of text anyone can see.

What we refused to break

We did not invent a rival language. We did not trap a book in a binary format, a database, or a subscription. MarkBreak is Pandoc Markdown — readable as ordinary text. Processors that meet an unknown line may ignore it; humans never have to.

The name

Mark: Markdown, and the author's mark on a manuscript — this is a chapter, start here. Break: //break, the break the file itself can say.

Our creed

Write plain. Mark the role. Break the page — in the file.
Then let Word, InDesign, or the press do the dressing up.

Read the specification, check the source, or open a manuscript and type //break on its own line.
